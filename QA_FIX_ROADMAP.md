## 6. Зависимости между исправлениями

```
P0-001 (CSRF mismatch)  →  блокирует все POST-операции, включая создание записей в E2E-сценариях
P0-002, P0-003 (маршруты вендоров/имущества)  →  необходимы для E2E-001 (создание поставщика → документ)
P1-001, P1-002 (списки вендоров/имущества)  →  необходимы для полного функционала управления записями
P0-004 (мобильное меню)  →  блокирует использование на мобильных устройствах
P1-004, P1-005 (прокрутка планшетов)  →  зависят от CSS, независимы от остальных
P1-007 (фокус клавиатуры)  →  независимое улучшение доступности
```

**Порядок исправлений:**
1. **Сначала:** P0-001 (CSRF) — без этого невозможно проверить любые другие функциональные исправления
2. **Затем:** P0-002, P0-003 (маршруты создания вендора/имущества) — открывают доступ к формам
3. **Затем:** P1-001, P1-002 (списки вендоров/имущества) — завершают функционал управления записями
4. **Параллельно:** P0-004, P1-004, P1-005 (CSS/адаптивность) — независимы от бэкенда
5. **После исправлений P0/P1:** повторный прогон всех тестов (Этап 3 → Этап 6)
